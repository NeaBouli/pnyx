# T-590: bundle the Semaphore depth-16 zkey (fix preparation, no build, no deploy)

**Node:** Mobile ZK vote path. `ProofModule.generateSemaphoreProof` → `uniffi.mopro.generateSemaphoreProof` → semaphore-rs `utils.rs::download_zkey(16)` → Groth16 prover. The server-side verification boundary (`apps/api/routers/zk.py`, pinned VK) is unchanged.

## Finding (CODEX-REVIEW ZK-ZKEY: HIGH, anonymity/correlation; soundness not affected)

- The prebuilt `libsemaphore_bindings.so` loads the proving key at proof time from `https://snark-artifacts.pse.dev/semaphore/4.13.0/semaphore-16.zkey` (reqwest/native-tls), with no integrity pin.
- semaphore-rs `src/utils.rs:42-57` (public upstream source): `dest = temp_dir()/semaphore-4.13.0-<depth>.zkey`; it downloads only `if !dest_path.exists()`. `ProofModule` points `TMPDIR` at `filesDir/semaphore-prover`, so the file persists after the first download.
- Consequence: the first vote per installation contacts a third-party server at vote time (IP and time). A foreign zkey cannot forge accepted proofs, because the server verifies against its own pinned VK (`6ef3f6ae…`), but it can block proof generation (DoS).
- `apps/mobile/app.json` sets `zkSemaphoreEnabled: true`, so the path is active in production builds.

## Integration plan (build phase, after the Mac load clears and the build slot is released)

1. `ProofModule.prepareWritableProverDirectory()`: before every proof, verify `TMPDIR/semaphore-4.13.0-16.zkey` against the pinned SHA-256 (constant generated from the manifest). If it is absent or mismatched, copy the bundled asset atomically (write `.tmp`, verify, rename) and verify again. If that still fails, throw `ProofStorageError` before calling the prover: fail closed, so the library's download branch is never reached.
2. Reject any tree depth other than 16 in `generateSemaphoreProof` (only one artifact is bundled).
3. KAT on a 16 KB AVD and a normal emulator (together with T-589):
   - a proof generated with the bundled zkey is accepted by the server verifier (pinned VK)
   - a mutated asset in TMPDIR is replaced or rejected before proving
   - network disabled during the proof: generation still succeeds
4. Remove the network-error retry path in `ProofModule` once no download remains.
