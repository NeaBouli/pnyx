# T-590: bundle the Semaphore depth-16 zkey (fix preparation, no build, no deploy)

**Node:** Mobile ZK vote path. `ProofModule.generateSemaphoreProof` → `uniffi.mopro.generateSemaphoreProof` → semaphore-rs `utils.rs::download_zkey(16)` → Groth16 prover. The server-side verification boundary (`apps/api/routers/zk.py`, pinned VK) is unchanged.

## Finding (CODEX-REVIEW ZK-ZKEY: HIGH, anonymity/correlation; soundness not affected)

- The prebuilt `libsemaphore_bindings.so` loads the proving key at proof time from `https://snark-artifacts.pse.dev/semaphore/4.13.0/semaphore-16.zkey` (reqwest/native-tls), with no integrity pin.
- semaphore-rs `src/utils.rs:42-57` (public upstream source): `dest = temp_dir()/semaphore-4.13.0-<depth>.zkey`; it downloads only `if !dest_path.exists()`. `ProofModule` points `TMPDIR` at `filesDir/semaphore-prover`, so the file persists after the first download.
- Consequence: the first vote per installation contacts a third-party server at vote time (IP and time). A foreign zkey cannot forge accepted proofs, because the server verifies against its own pinned VK (`6ef3f6ae…`), but it can block proof generation (DoS).
- `apps/mobile/app.json` sets `zkSemaphoreEnabled: true`, so the path is active in production builds.

## Integration plan (build phase, after the Mac load clears and the build slot is released)

1. `ProofModule.prepareWritableProverDirectory()`: before every proof, verify `TMPDIR/semaphore-4.13.0-16.zkey` against the pinned SHA-256 (constant generated from the manifest). If it is absent or mismatched, copy the bundled asset atomically (write `.tmp`, verify, rename) and verify again. If that still fails, throw `ProofStorageError` before calling the prover: fail closed, so the library's download branch is never reached.
2. Reject any tree depth other than 16 in `generateSemaphoreProof` **and** in `verifySemaphoreProof`. In `semaphore-protocol 0.1.0`, `verify_proof` (proof.rs:201) also calls `download_zkey` with the depth taken from the proof itself, so a proof claiming another depth would trigger a download at verify time. Both call sites use `.expect(...)`, so a failed download panics inside the library; pre-placement removes that path.
3. KAT on a 16 KB AVD and a normal emulator (together with T-589):
   - a proof generated with the bundled zkey is accepted by the server verifier (pinned VK)
   - a mutated asset in TMPDIR is replaced or rejected before proving
   - network disabled during the proof: generation still succeeds
4. Remove the network-error retry path in `ProofModule` once no download remains.
5. Placement runs before **every** `generateSemaphoreProof` and **every** `verifySemaphoreProof`, not only at app start: `TMPDIR` is `filesDir/semaphore-prover`, which Android does not clear by itself, but "clear data" or a reinstall does. The check covers size and SHA-256; on a mismatch the file is replaced atomically.
6. Network: Android offers no per-library network block inside the app process. Evidence therefore comes from tests: generate and verify succeed with the emulator in airplane mode, and with the bundled asset removed the wrapper fails closed with a clear `ProofStorageError` before the library is called, so neither the download nor the library's `.expect()` panic can run.

## Build phase result (2026-10-04)

Implemented on top of T-589 (#448, JNA 5.19.1). This PR's base is `agent/claude/T-589`.

- `BundledZkey.kt` (no Expo dependency):
  - `ensure()` checks size and SHA-256 of `filesDir/semaphore-prover/semaphore-4.13.0-16.zkey`
  - on a mismatch it copies the APK asset to `.tmp`, verifies it and renames it
  - otherwise it fails closed with `ZkeyException`
  - also contains `requireSupportedDepth()` and `depthOf(proofJson)`
- `ProofModule.kt`:
  - `generateSemaphoreProof`: depth 16 is required, then placement, then the prover
  - `verifySemaphoreProof`: the proof's declared depth must be 16, then placement, then verify
  - the network-retry path is removed
  - errors are `CodedException`s (`UnsupportedDepth`, `ProofStorageError`, `ProofGenerationError`, `ProofVerificationError`)
- Offline KAT (`SemaphoreKatTest`): the test APK declares **no INTERNET permission**. Results on arm64 (SM-G930F, Android 8.0); `ekklesia.gr` untouched and the test APK uninstalled:
  - `deterministicOutputsAndOfflineProofWithBundledZkey`: the T-589 known answers hold, and the proof generates and verifies offline
  - `alteredZkeyIsReplacedBeforeUse`: an altered file is replaced and no `.tmp` is left behind
  - `foreignDepthIsRejectedBeforeTheProver`: depth 20 is rejected, and malformed JSON yields depth -1
- Server acceptance: the device proof (fixture `apps/api/tests/fixtures/semaphore_t590_device_proof.json`) is accepted by `services.zk_groth16_verifier.verify_semaphore_proof` with the pinned VK (`6ef3f6ae…`), and a tampered message is rejected. This is pinned in `test_zk_artifact_manifest.py` (4/4 pass); a mutated proof point was also rejected in a manual check.
