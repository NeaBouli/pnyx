# Root Cause

`POST /api/v1/municipal/vote` prüft zuerst per SELECT auf Duplikate und fügt danach per INSERT ein. Zwei parallele identische Requests kommen beide durch den Pre-Check. Die Constraint `uq_diavgeia_vote (ada, nullifier_hash)` hat zwar eine Doppelzählung verhindert, aber der Verlierer bekam einen unbehandelten IntegrityError, also einen 500. Außerdem wurde nicht zurückgerollt, und die Session blieb mit `PendingRollbackError` unbrauchbar.

# Fix

`db.add` und `commit` stehen jetzt in einem `try`-Block. Bei `IntegrityError` wird zurückgerollt; handelt es sich um einen Verstoß gegen `uq_diavgeia_vote` (23505), wird ein 409 mit derselben Meldung wie beim Pre-Check zurückgegeben, andernfalls wird der Fehler erneut geworfen. Bei jeder anderen Exception wird ebenfalls zurückgerollt und erneut geworfen.

- Constraint und DB-Backend: vorhandene `uq_diavgeia_vote` (Model und Alembic `g001a2b3c4d5`). Getestet mit PostgreSQL 16.14 (`postgres:16-alpine`, asyncpg 0.31.0, SQLAlchemy 2.0.52) und SQLite (aiosqlite).
