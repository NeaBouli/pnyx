# T-589: Android 16 KB page support (JNA 5.19.1)

**Node:** Mobile native packaging. `modules/semaphore-react-native/android/build.gradle` (JNA AAR) → merged `lib/<abi>/libjnidispatch.so` in the APK/AAB → Android loader on 16 KB-page devices. The ZK vote path stays disabled (kill switch, #447); this PR does not re-enable it.

## Root cause

- Play Console: the active AAB (versionCode 61 / 1.0.32) does not support 16 KB pages.
- In the closest local release bundle (v1.0.31, vC60), every 64-bit `.so` is aligned except `lib/x86_64/libjnidispatch.so` (LOAD align `0x1000`). It comes from `net.java.dev.jna:jna:5.13.0@aar`; JNA 5.14.0 has the same problem, JNA 5.19.1 is aligned.
- The repo also vendored `jniLibs/arm64-v8a/libjnidispatch.so`, byte-identical to JNA 5.13.0 (SHA-256 `95fd6129757ceae7…`). With only the version bump, JNA 5.19 classes would run against the 5.13 native library on arm64, which JNA rejects at runtime. The vendored copy is therefore removed, and the AAR supplies the matching library for every ABI.

## Change

- `implementation("net.java.dev.jna:jna:5.13.0@aar")` → `5.19.1@aar`.
- Delete `src/main/jniLibs/arm64-v8a/libjnidispatch.so` (JNA 5.13 copy, native version 6.1.6).
- `src/androidTest/…/SemaphoreKatTest.kt` plus test-only manifest (INTERNET) and test dependencies: a known-answer test for the native Semaphore bindings.
- Module `packagingOptions.jniLibs.pickFirsts` for `libc++_shared.so`: this only affects the module's test APK, since React Native ships the same library.

## Semaphore KAT (arm64, SM-G930F, Android 8.0)

The Semaphore native libraries exist only for arm64-v8a, so this ran on a real arm64 device, not an x86_64 emulator. The test APK (`expo.modules.semaphore.test`) was uninstalled after every run; the installed `ekklesia.gr` app was not touched. Runs used React Native's `libc++_shared.so`, as the app bundle does.
