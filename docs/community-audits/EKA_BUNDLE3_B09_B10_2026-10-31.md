**Consumer drift gate.** `scripts/project_fact_consumers.json` stores publication templates, with named slots instead of duplicate numeric facts. `project_facts.py --check-consumers` verifies rendered lines across HTML body copy, metadata, structured data, separated metric cards, README and llms anchors. Missing or duplicated registered consumers fail. `--claims` additionally scans public HTML/Markdown/llms/README and now exits nonzero for an unlabelled mismatch or imprecise lower bound. Historical exemptions apply only to the next count after a dated label in the same clause and visible text run or locale translation; matching counts also consume that label. Sentence/semicolon boundaries and explicit current-claim wording end the exemption. Another claim on the same physical line, another locale, metadata or a hidden attribute cannot inherit it. The audit label now sits immediately before its 188-endpoint claim, after the separate router count. Inactive module subsets are checked against the inactive count, and explicitly included subsets against the listed-module bound. The numbering ceiling is no longer accepted as a listed-module count.

CI has an explicit consumer drift step: artifact freshness, rendered consumers/claims and wiki publication must all pass. Tests change one locale, separated metrics, cost slots, shared facts and Markdown to prove the gates fail on drift. Exact inventory fingerprints are extended only for the changed community/wiki pages, and the audit page remains protected by an exact whole-page digest. The landing schema-card correction has an exact bilingual replacement in `approved_audit_delta.py`, enforced through the existing landing preservation checker. The frozen R0 inventory is unchanged.
